# M15 — The island's panel: wallpaper, media and apps

Implementation spec. Read `CLAUDE.md` first.

**Status (2026-10-29):** **built** on `m15/island-panel` (stacked after `m14/island`), at the
product owner's request: *"the pill to have the functionalities in Elissa, like the wallpaper
change"*. Choices made the same day: **wallpaper switcher, media controls, open and pinned apps**
(not the system and network widgets); **a click expands a panel**. D-030 accepted the same day.
Steps 2–5 built with their checks (`M15-acceptance.md`). The modules' settings and pins live in
`%APPDATA%\kairos\island.db` (Elissa's key-value store, kept), not in `kairos.db`.

## 1. Goal and scope

The pill becomes Elissa-like: **a click expands it into a panel** under the top of the screen, with
tabs, and Esc, a click on the pill or a click elsewhere folds it back.

| Tab | What it does |
|---|---|
| **Home** | Kairos's state (as the pill), the date and time, and an **Ask** field that opens the quick box; the open apps' icons |
| **Media** | What is playing in any app (Spotify, a browser tab, VLC, the Windows player): title, artist, cover, progress; play/pause, previous, next |
| **Wallpaper** | Thumbnails of a folder the Master chooses; next, previous, or a click on one; one monitor or all |
| **Apps** | **Open apps**: icons of the apps with a window open, a click brings it to the front, right-click then the red × asks it to close (it can still ask to save). **Pinned apps**: a grid the Master fills from the Start menu and Store apps, a click launches |

The pill itself keeps what M14 gave it (state, microphone, menu); a click now expands instead of
opening the quick box (the quick box stays one click away, under Ask, and on Ctrl+Alt+K).

Out of scope: Elissa's system and network widgets (not chosen), her audio visualiser (it animates
all the time: Elissa measured a third of a core for a full-rate animation in such a window), a
rotation timer or a folder watcher for wallpapers, Elissa's command router. **Kairos itself can't
use these yet** (no "next wallpaper" for the model): a later milestone can expose them as plugin
tools behind the rules.

## 2. Where the code comes from

All four are **ported from Elissa** (`Desktop/Projects/Elissa/src-tauri/src/modules/`), the
product owner's own project on the same stack (Tauri 2, React, Rust, the same `windows` crate
version), and adapted to Kairos's conventions (`thiserror` errors, one module per concern, Kairos's
tests and charter):

| Elissa module | Lines | Windows mechanism | Notes for Kairos |
|---|---|---|---|
| `wallpaper` (+ `core/png.rs`) | 650 | `IDesktopWallpaper` (per monitor), shell thumbnails | jpg, jpeg, png, bmp; the folder is read when the tab opens; the current index is kept |
| `media` (`smtc`, `art`, `state`) | ~1,000 of 1,658 | WinRT System Media Transport Controls | Event driven, no polling; subscribed **only while the Media tab is on screen**; titles and covers never logged or stored (Elissa's privacy rule, kept). Without `viz` and the fake player |
| `openapps` | 524 | `EnumWindows`, the process's executable or Store AppUserModelID, `WM_CLOSE` | Window titles are never read into the list (page and document names stay private); only windows from the latest scan can be targeted; no moving, resizing or force-killing |
| `pinned` (+ `core/shell_icon.rs`) | 968 | Start menu shortcuts and the shell's AppsFolder (Store apps), icons as PNG | Pins in `kairos.db` (name, launch target, order); a pin is created only from a listed app and launched by its id: no command text ever comes from the page |

## 3. Decisions

- **D-030 — The island's panel ports Elissa's wallpaper, media, open-apps and pinned-apps modules —
  Proposed.**
  - **No new crate.** More features on the `windows` crate (`=0.62.2`) Kairos already depends on,
    the ones Elissa uses for these modules: `Win32_UI_WindowsAndMessaging`, `Win32_UI_Shell`,
    `Win32_UI_Shell_PropertiesSystem`, `Win32_System_Com`, `Win32_System_Variant`,
    `Win32_System_Threading`, `Win32_Graphics_Gdi`, `Win32_Storage_EnhancedStorage`,
    `Win32_Storage_Packaging_Appx`, `Win32_System_WinRT`, `Media_Control`, `Storage_Streams`.
  - **The island window grows when expanded** (300 × 40 → about 600 × 380 logical px, anchored
    top-centre) and shrinks back: the window always has the size of what shows, so still no cursor
    polling (M14's choice).
  - Folding back on "a click elsewhere" uses the window losing focus. The panel takes the focus
    when the Master clicks the pill (a real click gives it), so Windows reports leaving it; the
    hotkey path that Elissa found unreliable isn't used.
  - These are the Master's own clicks, so they don't go through the Kairos rules (which judge
    the model's actions). Closing an app keeps Elissa's two-step (right-click, then the ×).

## 4. Steps

### Step 1 — Spec, D-030
**Check:** the product owner reads it.

### Step 2 — The panel
The island expands into a tabbed panel and folds back (Esc, the pill, losing focus); the window
resizes anchored top-centre; Home tab with the clock, Kairos's state, Ask → quick box.
**Check:** TS tests for expand and fold; Rust tests for the expanded placement (100/150 %);
screenshots dark and light.

### Step 3 — Open and pinned apps
Port `openapps`, `pinned`, `shell_icon`, `png`; a `pinned_app` table in `kairos.db`; the Apps tab
with the picker.
**Check:** the ported tests (Elissa's, adapted), plus "a pin can only launch by its id"; live:
focus Notepad from its icon, pin Calculator and launch it.

### Step 4 — Wallpaper
Port `wallpaper`; Settings ▸ Kairos ▸ Island gains "Wallpaper folder".
**Check:** the ported tests; live: next and previous **change the product owner's wallpaper**, so
the agent records the current wallpaper first and puts it back after (Elissa's rule 13), and says
so before doing it.

### Step 5 — Media
Port `media` without `viz` and `fake`; the Media tab.
**Check:** the ported tests; live with something playing (the product owner's, or a test file in
the Windows player); CPU with the Media tab hidden: no subscription, nothing read.
