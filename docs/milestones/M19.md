## 1. Goal and scope

Settings ▸ Kairos ▸ **Skills**: see what Hermes knows how to do, find new skills in the hub, read one
and see its security scan before installing it, and remove it again.

Today Hermes has 51 built-in skills and none from the hub, and Kairos shows none of this.

**In scope:** the installed list, turning a skill off and on, searching the registries, inspecting,
scanning, installing, uninstalling, checking for updates, updating, re-auditing.

**Out of scope:**
- Overriding the scanner (`--force`), from anywhere in Kairos, ever.
- Publishing skills, taps (custom sources), snapshots, the `/learn` command.
- Editing a skill's text. Kairos's own skills stay protected by the `kairos-skills` rule.
- Limiting a skill to Kairos's conversations. Hub skills belong to the Hermes profile, so they are
  also available from the Hermes command line and any messaging platform.

## 2. What Hermes offers (read 2026-11-01, Hermes 0.22.5)

| Need | Command | Output | Notes |
|---|---|---|---|
| Search | `hermes skills search <q> --source … --limit … --json` | **JSON**: `name`, `identifier`, `source`, `trust_level`, `description` (seen live) | The source of the Find tab |
| Installed | `hermes skills list [--source hub]` | A table only | Long names are cut unless `COLUMNS` is wide; with `COLUMNS=220` the full name shows (seen live) |
| Read | `hermes skills inspect <id>` | A framed text panel | Prints a preview of `SKILL.md`, which Hermes may shorten |
| Install | `hermes skills install <id> --yes` | Text; exit code | Runs the scan, and the policy below, either way |
| Remove | `hermes skills uninstall <name> --yes` | Text; exit code | Hub-installed skills only |
| Updates | `hermes skills check [name]` | Text | Compares the stored hash with upstream |
| Re-scan | `hermes skills audit [name]` | Text | |
| On or off | `hermes config set skills.disabled '[…]'` | | Hermes's reference lists it; `hermes skills config` is interactive |

**`GET /v1/skills` can't be used:** it returns a 500 error, on 2026-10-23 (the recorded fixture) and
again live on 2026-11-01. This is why the list comes from the CLI.

**The scan policy, in Hermes (`tools/skills_guard.py`):**

| Source's trust | Safe | Caution | Dangerous |
|---|---|---|---|
| `builtin` (official) | allow | allow | allow |
| `trusted` (`openai/skills`, `anthropics/skills`, `huggingface/skills`, `NVIDIA/skills`) | allow | allow | **block** |
| `community` (everything else) | allow | **block** | **block** |

`--force` overrides a caution block; nothing overrides a dangerous verdict on trusted or community
sources.

**Two things read from Hermes's source that shape this design (`hermes_cli/skills_hub.py`):**
- **A scan without installing.** `install` without `--yes` scans, prints the report, then asks
  `Confirm [y/N]:`, and end of input counts as no, removing the quarantined copy. So with no console
  attached it should act as a preview. **Not yet seen running:** Step 2 confirms it before anything
  relies on it.
- **`hermes skills update` always installs with `force=True`.** So an update can pass a caution
  block that a fresh install would stop. Kairos doesn't use it (§4).

## 3. The page

**Installed.** Skills grouped by category, each group folding open and shut as in the model menu, with
a filter. Each row: name, description, source (Built-in, Hub, Yours), a switch. Hub skills also have
Update (when one exists) and Remove. A **Check for updates** and a **Re-scan** button sit above the
list. The switch is disabled on Kairos's own skills.

**Find.** A search box and a source filter. Each result: name, description, its source, and a trust
badge: **Official**, **Trusted** or **Community**. A click opens the skill's page.

**A skill's page, the order is the point:**
1. **Who it comes from:** source, identifier, trust. For Community: "Anyone can publish here. A skill
   is instructions Kairos will follow."
2. **What it says:** the `SKILL.md` text, always shown as plain text. It is untrusted: never rendered
   as Markdown, no links or images fetched.
3. **Scan** (a button): runs the preview and shows the verdict and the findings in words.
4. **Install**: enabled only after a scan that passed. If the scan blocked it, the page says why, and
   there is no button to override.

After an install: "Installed. Open conversations learn about it on their next message."

## 4. How it works

- **A new `skills.rs`:** one pure function builds each command's arguments, and one parses each
  output, tested against recorded fixtures. `run_cli` (M18) gains a time limit per call: search,
  scan and install download things, and 15 s isn't enough.
- **`--force` can't be sent:** no function can build it, and a test says so.
- **Identifiers come from search results**, checked against a strict pattern before use, so text from
  a registry can't become a command-line option (one beginning with `-` is refused). Direct URLs
  are out of scope for this milestone.
- **Update, without `hermes skills update`:** Remove, then Install, through the same scan. If the new
  version fails the scan, the skill stays removed and the page says so. It warns first when you've
  edited the skill locally, because that copy would be lost.
- **Plain output:** every call sets `NO_COLOR=1`, a wide `COLUMNS`, and UTF-8 output.
- **No model access:** this page is for the Master's clicks. Nothing here gives the model a new tool.
- **Rules still apply:** whatever a skill leads the model to do passes the Kairos rules as usual. An
  installed skill's scripts run only through the model's tools, under those rules.
- **Not asked of Hermes:** no edit to Hermes's code. Skills land in `~/.hermes/skills`, Hermes's own
  folder, through its own installer.

## 5. Decisions

- **D-039 — Kairos manages skills through `hermes skills`, and never overrides the scan — Proposed.**
  Kairos lists, finds, scans, installs and removes through Hermes's own commands, from the Master's
  clicks, showing the skill's text and scan verdict before installing. It never sends `--force`, and
  avoids `hermes skills update`, which forces. A skill is instructions the model will follow, so a
  bad one is a prompt injection installed on purpose: the scan is one defence, reading it is a second,
  and the Kairos rules behind every tool call are the third.

## 7. Ask the product owner, don't guess

1. **Kairos may install and remove skills and change `skills.disabled`, from your clicks.** It's a
   change to Hermes's skills and configuration. Recommended: yes; it's what the feature is.
2. **One community skill downloaded for the Step 2 probe.** The permission system stopped this
   when I tried it on 2026-11-01, rightly, as it fetches third-party content: it would be fetched into
   quarantine and scanned, not run or installed, and then removed. Without it, the block path is
   checked from the source only. Recommended: yes, and you approve the prompt when it appears.
3. **Community skills at all.** Recommended: allowed, after the warning, the text and a passed scan.
   The stricter choice: Official and Trusted only, and you can widen it later.
4. **Update as Remove then Install,** rather than Hermes's forced update. The cost: a new version that
   fails the scan leaves you without the skill. Recommended: yes; that failure is the scan doing its job.
