# M8 — Always-there assistant

Implementation spec. Read `CLAUDE.md` and `docs/milestones/M3.md` §6 (plugin tools) first.

**Status (2026-10-25):** built ahead of the earlier milestones' sign-off, at the product owner's
request. Branch `m8/always-there`, which starts from `m7/isolation-models`. Checks marked
**(on the PC)** are collected in `docs/TESTING.md`.

---

## 1. Goal and scope

- **A global hotkey** opens a small Kairos box over any app: type a question, get the answer there,
  Esc to hide.
- **"What's on my screen?"**: a screenshot, after the user allows it, read by Hermes's
  `vision_analyze` (natively on a vision model, or through Hermes's helper vision model)
  [source: tools-reference.md].
- **Scheduled jobs** from the app through Hermes's `/api/jobs` (list, create, pause, resume, run
  now, delete) [source: api-server.md and `cron/jobs.py`], all under the same rules.

## 2. Decisions

- **D-021 — The quick box is a second Tauri window opened by a global shortcut; screenshots are a
  plugin tool that asks every time — Accepted (on the product owner's delegation, 2026-10-25; to
  confirm at testing).** The shortcut needs Tauri's official `tauri-plugin-global-shortcut`
  (`=2.4.1`, the one new dependency). The default is **Ctrl+Alt+Space** (the roadmap's Alt+Space is
  Windows's own window-menu key and PowerToys Run's; it can be chosen in Settings). The screenshot
  is a Kairos plugin tool, `screen_capture`, written with `ctypes` (no new dependency): the starter
  rule `screen-capture` makes **every** capture ask, and the image stays in
  `%APPDATA%\kairos\screens` (last 20 kept).

## 3. The quick box

- A frameless, always-on-top window (`quick`, 640 × 360) hidden until the hotkey; the hotkey
  toggles it; Esc or losing focus hides it.
- It runs its own chat in one conversation per day (titled, like every Kairos conversation, by
  its first request), with the same rules, approval cards, model and cost line as the main window
  (it is the same chat code in a second window).
- "Open in Kairos" switches the main window to that conversation.
- The hotkey is set in Settings ▸ Quick box; a hotkey Windows refuses (already taken) is reported
  there.

## 4. Screen

`screen_capture(display: "primary" | "all" = "primary")`: waits 0.6 s (so the quick box can hide
itself first), copies the screen with GDI (`BitBlt`, `GetDIBits`), writes a PNG with the standard
library (`zlib`), keeps the last 20, and returns the path with the instruction to call
`vision_analyze` on it. Windows only. The steering note (M3) adds: "for questions about the screen,
call `screen_capture`, then `vision_analyze` on the path it returns".

The quick box hides while a `screen_capture` call runs and comes back when it ends.

## 5. Scheduled jobs

A **Scheduled** page in the sidebar: each job's name, schedule ("every monday 9am"), next and last
run, last status or error; buttons Run now, Pause/Resume, Delete (asks first); a form for a new job
(name, schedule in Hermes's words or cron, prompt). Jobs run inside Hermes, so every tool call goes
through the Kairos rules; an `ask` rule in an unattended job has nobody to answer and doesn't run.

Two starter rules (ask) cover the **agent** creating, changing or removing jobs on its own:
`scheduled-jobs` for the `cronjob_manage` tool (actions create, update, resume, remove) and
`scheduled-jobs-cli` for `hermes cron add/create/edit/resume/remove` in a shell (a rule's command
patterns only apply to shell tools, so one rule can't cover both). Scheduling unattended work is the
user's call. Listing, pausing and running an existing job don't ask. Jobs made on the Scheduled
page go straight to Hermes's `/api/jobs`, not through the agent, with `deliver: "local"` so their
output stays in Hermes and nothing is posted anywhere.

wording; policy tests for `scheduled-jobs`. **(On the PC)** create "every 2m: say hello", see it
run, pause, resume, run now, delete.
