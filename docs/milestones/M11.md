# M11 — Memory

Implementation spec. Read `CLAUDE.md` first.

**Status (2026-10-27):** being built on `m10/persona` (stacked after M10), at the product owner's
request. Checks marked **(on the PC)** are collected in `docs/TESTING.md`.

## 1. Goal and scope

Kairos should remember its Master, and the Master should see, and be able to undo, what it
remembers.

- **What Kairos remembers** (Settings ▸ Kairos ▸ Memory): everything Hermes keeps about you, in
  one place, read-only:
  - *About you* — Hermes's `USER.md` profile entries;
  - *Kairos's notes* — Hermes's `MEMORY.md` entries;
  - *Facts* — the holographic provider's fact store, newest first, with its category and how
    much Kairos trusts it.
  Each with how full it is (Hermes caps the two files in characters).
- **Forget**: one button per item. Kairos is asked, in its own small conversation, to remove
  exactly that item with its own memory tool (`memory` remove, or `fact_store` forget, which
  deletes a fact with its history). Hermes and the plugin keep ownership of their files; Kairos
  never edits them.
- **Remember more**: one line in the Kairos persona tells it to keep lasting facts about its
  Master with the memory tools, and never secrets (chosen 2026-10-27; the free model had saved
  nothing in three days).
- **The provider trial**: Hermes's `holographic` memory provider (chosen 2026-10-27).

Out of scope: editing an entry in place (forget it and say the right thing instead), graph
memory, cloud providers.

## 2. Decisions

- **D-026 — Kairos shows Hermes's memory read-only and forgets through Hermes; the provider is
  holographic — Accepted** (the product owner, 2026-10-27). Hermes exposes memory only on its
  dashboard server, which Kairos's contracts don't cover, so Kairos reads
  `<HERMES_HOME>\memories\USER.md`, `MEMORY.md` (entries separated by `§`) and
  `<HERMES_HOME>\memory_store.db` (SQLite, opened read-only), and changes nothing in them itself.
  Forgetting is a request to Kairos in a conversation named "Forget a memory", which the sidebar
  hides; it goes through the Kairos rules like any request. Provider: `holographic` 0.18.3
  (MIT, pinned in Hermes's catalog), local SQLite with full-text search in English, French,
  Arabic and more; no API key, network or model calls with its defaults. Installed with
  `hermes plugins install holographic --yes-deps --enable` (it added numpy and
  snowballstemmer to Hermes's environment); the only line it changed in Hermes's `config.yaml`
  is `memory.provider: holographic`, and the file before it is in
  `%APPDATA%\kairos\backups\hermes-config.yaml.before-holographic`. Undo: `hermes memory off`.

## 3. Steps

### Step 1 — Spec, the provider, the persona line
This file, D-026, TESTING; holographic installed and enabled (done 2026-10-27, gateway restarted);
the persona line saved through Settings ▸ Persona (backup kept).

### Step 2 — Reading memory (Rust)
`memory.rs`: parse the two files (`§` entries), read the facts read-only, the provider and the
limits from Hermes's CLI. **Check:** Rust tests on throwaway files and a throwaway database: entries
split, empty or missing files, a fact store that doesn't exist yet, a locked database.

### Step 3 — Settings ▸ Memory
The three lists, how full each file is, Forget (asks first), Refresh. **Check:** TS tests for the
forget request's wording and the "how full" figure; lint, tsc. **(On the PC)** tell Kairos something
about yourself, see it appear; forget it, see it go.

### Step 4 — Live check
A fact told to Kairos lands in the store or USER.md; forget removes it.
