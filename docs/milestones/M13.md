# M13 — Rich answers: tables, diagrams and images

Implementation spec. Read `CLAUDE.md` first.

**Status (2026-10-28):** **built** on `m13/rich-answers` (stacked after `m12/browser`), at the
product owner's request: answers that can show *"tables, diagrams, other shapes or simple images
while conversing, only in good times, not stuffed anywhere"*. D-028 and the `mermaid` dependency
(11.17.2, exact) accepted the same day. Steps 2–5 built with their checks
(`M13-acceptance.md`); Step 6 is the product owner's.

## 1. Goal and scope

Kairos answers like a good document, not a chat log: a **table** when things are compared, a
**diagram** when something has steps or parts, a **chart** when numbers compare or change, a
**picture** when the Master asks for one. And only then: a short answer stays a sentence.

- **Tables** — Markdown tables, drawn in the charter style; wide ones scroll sideways; a Copy
  button gives tab-separated text that pastes into Excel.
- **Diagrams and charts** — the model writes [Mermaid](https://mermaid.js.org) (flowcharts,
  sequence, timelines, mind maps, pie and bar/line charts, Gantt), Kairos draws it. The source
  is one click away.
- **Shapes and simple pictures** — the model may draw a small illustration as SVG (a logo
  sketch, a floor plan, an icon); Kairos shows it as an image.
- **Images** — pictures Hermes generates (`image_generate`) or captures (screenshots), inline,
  click to enlarge, with a Save button.
- **Only when it helps** — guidance to the model every turn in Kairos conversations (§4), and
  voice that says "there's a table on screen" instead of reading pipes aloud.

Everywhere answers appear: the main chat and the quick box (narrower: tables scroll, diagrams
fit the width, images are thumbnails).

Out of scope: maths notation (LaTeX), editing a diagram in Kairos, generating video, charts from
files the Master drops in (a later milestone could add that).

## 2. What exists today (read 2026-10-28)

- **Kairos's chat renderer** is its own small Markdown reader (`app/src/features/chat/markdown.ts`
  → `MarkdownView.tsx`): paragraphs, headings, lists, quotes, links, inline code and code blocks.
  It produces plain data rendered as React elements; **model text is never inserted as HTML**.
  Tables show as raw `| a | b |` lines; a Mermaid diagram shows as a code block; images don't
  show. No Markdown or diagram library is installed (the app's dependencies are React, Zustand,
  Tauri's API).
- **Hermes and images** (Hermes 0.22.5's code):
  - a tool or the model puts `MEDIA:<path>` in a reply to attach a file (screenshots:
    `browser_vision` says so; `image_generate` saves its picture);
  - on `/v1/runs`, the **final** answer (`run.completed`'s `output`, which Kairos keeps) has
    each image `MEDIA:` path replaced by `![image](data:image/png;base64,…)`: PNG, JPEG, GIF,
    WebP or BMP, up to 5 MB, after Hermes's own path check. The text that **streams** before it
    still holds the raw `MEDIA:C:\…` path;
  - a conversation reopened later comes from Hermes's history, which keeps the raw `MEDIA:` path;
  - `image_generate` uses FAL.ai: a `FAL_KEY`, or Nous's managed gateway on a subscription.
    **Step 1 (2026-10-28): not yet on this PC.** Asked for a picture, Hermes answered that its
    image app must first be connected on the Nous Portal (a connect link; its log shows a
    `CONNECTION_REQUIRED` from the image connector). Connecting it is the product owner's call.
    A screenshot through Hermes needed an approval each time (the model reached for file-system
    code), so no `MEDIA:` fixture was recorded; the display follows Hermes's code above, and the
    product owner's checklist includes one real screenshot.
- **Voice** (`speechText`, M9) already skips code blocks and reads image alt text; a table is
  read cell by cell.
- **Steering**: the plugin already adds short notes to the model before a turn (`pre_llm_call`,
  M3/M4/M8). That is where the "only when it helps" guidance goes.

## 3. Decisions

- **D-028 — Rich answers: Kairos draws tables itself, diagrams with Mermaid, and shows only images
  it can't be tricked with — Proposed.**
  - **Tables**: added to Kairos's own Markdown reader; no library.
  - **Diagrams**: the `mermaid` package (MIT), **the new dependency to approve**: an exact 11.x
    version, the newest at least two weeks old when Step 3 starts, pinned without `^`. It is
    loaded only when an answer contains a diagram (it is large: roughly 2–3 MB of script), with
    `securityLevel: "strict"` (no HTML labels, no click handlers; Mermaid sanitises its SVG).
    Its SVG output is the **one place** the chat inserts markup, and it comes from Mermaid, not
    from the model.
  - **Images**: only `data:image/png|jpeg|gif|webp` (what Hermes produces) and the model's ```` ```svg ````
    blocks, both shown with an `<img>` element: an SVG inside `<img>` can't run scripts or load
    anything. **No images from web addresses**: the model could otherwise make Kairos fetch a
    tracking URL; a web image shows as a link.
  - **Older conversations**: a `MEDIA:` path in history is shown through a Rust command that
    reads only images under Hermes's own folders (`image_cache`, Hermes's cache), up to 5 MB;
    anything else shows "image not available".
- **Image generation stays Hermes's** (`image_generate`): if Step 1 shows it needs a FAL key or a
  paid plan, that is the product owner's call, outside this milestone.

## 4. "Only when it helps": the guidance

Added by the plugin's `pre_llm_call` on Kairos's own conversations (session ids start with
`kairos-`), so Telegram or the CLI are unaffected:

> Format for Kairos's screen. Default to plain sentences; a short answer stays short.
> Use a Markdown **table** when comparing three or more things on two or more points, or when
> the Master asks for one. Use one **Mermaid diagram** (```` ```mermaid ````) for a process with
> steps or branches, how parts connect, a timeline, or when asked; keep it under 15 boxes. Use a
> Mermaid **pie or bar chart** for numbers that compare or change. Draw a small **SVG**
> (```` ```svg ````, under 20 KB) only for a shape or sketch words can't carry. Generate an
> **image** only when the Master asks for a picture. Never add a table, diagram or picture as
> decoration, and never more than one of them unless asked.

Measured in Step 5 on ten questions (a fact, a how-to, a comparison, a process, numbers over
time, a request for a picture…): the right form for each, and none on the plain ones.

## 5. Steps

### Step 1 — Spec and probe
This file; D-028 proposed. Probe Hermes: ask for a screenshot description with `MEDIA:` and for a
generated image; record what `run.completed` carries (a sanitised fixture, the image cut to a
tiny placeholder) and whether `image_generate` works here.
**Check:** the fixture; the answer to "does image generation work?" written into §2.

### Step 2 — Tables
`markdown.ts`: a `table` block (header, alignment row, cells with inline formatting, ragged rows
padded), a table still streaming shown as text until its alignment row arrives. `MarkdownView`:
charter styling, sideways scroll, Copy (tab-separated). Voice: "There's a table on screen."
**Check:** TS tests ("a pipe inside code doesn't split a cell", "a table without an alignment row
stays a paragraph"); screenshot through the debug port in the chat and the quick box.

### Step 3 — Diagrams and charts
The `mermaid` dependency (after approval). A ```` ```mermaid ```` block is drawn once its closing fence
arrives (while streaming: "Drawing…"); charter theme from the CSS tokens (dark and light); a
diagram that fails to parse shows its code with "Couldn't draw this diagram"; "Source" toggles the
code; fits the width in the quick box. Voice: "There's a diagram on screen."
**Check:** TS tests for when a diagram is drawn and the fallback; screenshots of a flowchart, a
sequence diagram, a pie chart, dark and light.

### Step 4 — Images and SVG
`data:image/…` images and ```` ```svg ```` blocks (under 100 KB) as `<img>`; web images as links;
`MEDIA:` lines hidden while streaming ("Image…"); click to enlarge, Esc to close; Save (to
Downloads, through Rust). History: `media_image(path)` in Rust, limited to Hermes's folders.
**Check:** TS tests (an `https:` image becomes a link; a `javascript:` or SVG data URL isn't
shown); Rust tests (a path outside Hermes's folders, `..`, a non-image, a 6 MB file are refused);
a screenshot of an answer with a picture.

### Step 5 — The guidance and the ten questions
The `pre_llm_call` note (§4) in the plugin; plugin tests (only `kairos-` sessions get it).
**Check:** the ten questions live, the form of each answer recorded in `M13-acceptance.md`.

### Step 6 — Acceptance (product owner, on the PC)
`docs/milestones/M13-acceptance.md`: compare three laptops (a table), "how does Kairos's wake
word work?" (a diagram), a plain question (no decoration), a request for a picture, the same in
the quick box, one spoken.
