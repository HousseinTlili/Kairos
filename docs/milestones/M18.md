# M18 — Your own AI providers

Implementation spec. Read `CLAUDE.md` and `docs/milestones/M7.md` §4 (the model menu) first.

**Status (2026-10-31):** built on `m18/providers` (stacked after `m17/automations`), at the product
owner's request: *"make it possible for me to add my own API to use the AI model I desire"*.
Accepted the same day with the recommended answers to §6 (D-038 Accepted); Steps 2–3 built
(`M18-acceptance.md`). **As built, §2 changed in two places:** a known provider's key is its line in
`.env`, not `hermes auth add` (which reads a key only from a console prompt or an argument), and
Copilot is a fine-grained token (`COPILOT_GITHUB_TOKEN`), since Hermes has no `auth add` sign-in
for it.

---

## 1. Goal and scope

Settings ▸ Accounts and models ▸ **Providers**: add the AI services Kairos may use, with your own
keys, and see their models appear in the model menu above the message box.

Three ways to add one:

| Kind | Examples | What the Master gives |
|---|---|---|
| **A known provider** | OpenAI, Anthropic, Google Gemini, OpenRouter, DeepSeek, xAI, Mistral, Groq, … (Hermes knows 40+) | its API key |
| **Your own endpoint** (OpenAI-compatible) | a self-hosted vLLM or LM Studio, a company gateway, LiteLLM, any `…/v1` API | a name, its address, its key, optionally its model names |
| **GitHub Copilot** | Copilot's GPT, Claude and Gemini models | a GitHub sign-in (a code to enter on github.com) |

The list shows every provider Hermes can use (the ones added here and the ones set up before),
with **Remove** for those added here and a **Test** that asks the provider for its models.

**Out of scope:** Hermes's default model and fallback chain (still `hermes model` and
`hermes fallback`); the per-conversation choice stays the M7 menu, which shows the new models by
itself because it reads `/api/model/options`. Local models stay Hermes Desktop's.

## 2. How Kairos adds them (read 2026-10-31, Hermes 0.22.5)

Only through Hermes's own commands and documented settings, never by editing its files by hand,
except one line in `.env` for a custom endpoint's key (as `scripts/setup.ps1` already does for
`API_SERVER_KEY`):

- **Known provider:** `hermes auth add <provider> --type api-key --label Kairos`, the key given on
  its standard input if Hermes reads it there, else with `--api-key` (then visible for a moment to
  programs running as the Master). Removed with `hermes auth remove <provider> Kairos`.
- **Own endpoint:** the key in Hermes's `.env` as `KAIROS_<NAME>_API_KEY`; the endpoint with
  `hermes config set providers.<name>` holding `api: <address>`, `key_env: KAIROS_<NAME>_API_KEY`
  and, when given, `models: [...]` (Hermes's documented `providers:` entry). The key is never in
  `config.yaml`. Removed with `hermes config unset providers.<name>` and the `.env` line deleted.
- **GitHub Copilot:** `hermes auth add copilot --type oauth` (the device-code sign-in Hermes
  documents, the same as Copilot CLI's), shown in a small console window where the Master reads the
  code and confirms on github.com. Hermes keeps the token.
- **Keys and Kairos:** Kairos keeps no provider key itself, and never prints, logs or shows one
  after it is saved (CLAUDE.md). The field is a password field; errors never quote it.
- **After a change**, Kairos asks Hermes for the model list again. If Hermes only reads new
  providers at start, Kairos says so and offers to restart the gateway (it waits for running
  requests first).

## 3. Decisions

- **D-038 — Kairos adds AI providers through Hermes's own commands; keys live only in Hermes —
  Proposed.** Hermes already speaks to every provider and keeps credentials (its credential pool
  and `.env`); Kairos only fills them in, through `hermes auth add` and `hermes config set`, plus one
  `.env` line per custom endpoint's key (referenced by `key_env`, so `config.yaml` never holds a
  key). The model menu (M7) needs nothing new. This is a change to Hermes's configuration made at
  the Master's request, each time from his own click.

## 4. Steps

### Step 1 — Spec, D-038
This document. **Check:** the product owner accepts it or changes it (§6).

### Step 2 — The commands (Rust)
List (`hermes auth list`, `/api/model/options`), add a known provider, add and remove an endpoint
(`.env` line + `providers.<name>`), Copilot sign-in in a console window, test (the provider's
models). **Check:** tests for the endpoint entry and the `.env` line ("a key with quotes or `#` is
written so Hermes reads it back whole", "removing an endpoint removes its key and nothing else"),
and that no error message holds a key.

### Step 3 — Settings ▸ Providers
The list, "Add a provider" (known / own endpoint / GitHub Copilot), Remove and Test. **Check:**
tests and screenshots.

### Step 4 — Live, with the Master's key (on the PC)
Add a real key or endpoint; its models in the menu; a conversation on one of them; Remove.

## 5. Definition of done

Each step's check run and shown; the (on the PC) checks in `docs/TESTING.md`; D-038 Accepted;
tests, lint and clippy clean; committed on `m18/providers`, not pushed.

## 6. Ask the product owner, don't guess

1. **Kairos may change Hermes's configuration for this** (credentials, a `providers:` entry, a
   `.env` line), each time from your click. Recommended: yes; it's what the feature is.
2. **Copilot** as a third way, with the plan and terms caveats in §7. Recommended: include it; you
   decide whether to sign in.
3. **Restarting the gateway** when Hermes needs it to see a new provider: Kairos offers it with a
   button. Recommended: offer, never by itself.

## 7. GitHub Copilot with GitHub Education (read 2026-10-31)

- **Students:** free through GitHub Education, but since March 2026 as the **Copilot Student** plan
  (not Copilot Pro): unlimited code completions, a monthly AI-credit allowance, and limited chat
  and agent use. Teachers reportedly get Copilot Pro. Activation at
  github.com/settings/education/benefits.
- **In Kairos:** Hermes supports Copilot as a provider (`copilot`, device-code sign-in). Kairos's
  requests are agent loops (many model calls per request, with tools), so a limited student
  allowance would be used up quickly.
- **Terms:** GitHub officially supports Copilot subscriptions in some third-party tools (OpenCode,
  January 2026, announced for paid plans). Hermes isn't one of the announced ones: it works, but
  is outside what GitHub has said it supports, more so on a student plan. Using it is the Master's
  call.
