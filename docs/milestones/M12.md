# M12 — Kairos in the Master's own browser

Implementation spec. Read `CLAUDE.md` first.

**Status (2026-10-27):** spec only, on `m12/browser` (stacked after `m10/persona`), at the
product owner's request: *"Plan letting Kairos use my real browser profile, with Kairos rules
for clicks and purchases first."* Nothing is built or switched on. Checks marked **(on the PC)**
go to `docs/TESTING.md` when their step is built.

## 1. Goal and scope

Kairos can already drive a browser: Hermes's `browser` toolset is on for Kairos's connection
(`fixtures/hermes-0.22.5/meta/toolsets.json`), on agent-browser 0.26 (Playwright) and a bundled
Chromium. But that browser is a fresh one: signed in to nothing. The goal is for Kairos to act
**as the Master** on the sites they are signed in to (mail, shops, accounts), and to **ask first**
before anything with consequences: buying, paying, sending, posting, deleting, confirming.

The order matters and is the product owner's: **the rules first**, then the profile. Steps 2–4
are useful on their own (they also guard today's fresh browser); Step 5 is the switch.

Out of scope: driving the Master's *open* browser window (Hermes's `browser.extension_control`
or `/browser connect`), Hermes's desktop control (`computer_use`, off), cloud browsers.

## 2. What Hermes does (read in Hermes 0.22.5's code, 2026-10-27; nothing changed)

- **Real-profile mode** is `browser.use_real_profile: true` in Hermes's `config.yaml` (default
  off; read on every call, so it needs no restart). Hermes then:
  - finds the default browser: on this PC **Brave** (`BraveHTML`), which it supports (Chrome,
    Edge, Brave, Chromium; not Beta/Dev/Canary channels);
  - copies the active profile's `Local State`, `Cookies`, `Login Data`, `Login Data For
    Account`, `Web Data` (saved passwords and autofill, which can include cards) and
    `Preferences` into a Hermes-owned folder with owner-only permissions;
  - starts the real `brave.exe` on that copy and drives it over its DevTools port. The Master's
    own Brave is never touched;
  - when the switch is turned off, **deletes the copies**.
- **On Windows the first copy needs Brave closed**: a running Brave locks its cookie database.
  While Brave is open, Hermes reuses the last complete copy without refreshing it, so Kairos is
  signed in as the Master was **at the last copy**; closing Brave lets the next browser task
  refresh it. If no copy exists yet and Brave is open, the task fails with a message, and Hermes
  offers `hermes browser close-profile`, which quits Brave (unsaved tabs lost): Kairos must ask.
- **A click carries only a reference**: `browser_click {"ref": "@e5"}`; `browser_type {"ref",
  "text"}`; `browser_press {"key"}`. The label is in the page snapshot the model received
  earlier, one element per line: `- button "Place order" [ref=e5]`. Kairos's plugin receives every
  tool's result (`post_tool_call`), so it can remember what each reference was.
- **Other ways to act on a page**, each needing its own rule:
  - `browser_console` with `expression`: any JavaScript in the page, which can click
    (`.click()`), submit, or read cookies and storage. Hermes's `browser.restrict_evaluate: true`
    blocks the cookie / storage / clipboard / network / form-value primitives (off by default);
  - `browser_cdp`: raw DevTools commands, anything at all;
  - `browser_dialog`: accepting a page's "Are you sure?" box;
  - `browser_vault`: fills saved passwords, cards (after the user confirms, per Hermes) and
    addresses without the secret entering the conversation;
  - `browser_exec`: Python through the browser helper; already guarded (M2,
    `browser-code-system-access`).

## 3. Decisions to take

- **D-027 — Kairos may use a copy of the Master's Brave profile, behind the Kairos rules —
  Proposed.** Changes Hermes's configuration (`browser.use_real_profile: true`,
  `browser.restrict_evaluate: true`), with a backup as for holographic (D-026). The product owner
  turns it on and off in Kairos (Step 5); off deletes the copies.
- **What the copy means, to accept with D-027:**
  - Hermes's folder holds a copy of the Master's cookies and saved passwords;
  - pages Kairos reads (mail, orders, bank pages) go to the model provider like anything else
    Kairos reads;
  - a page can contain instructions aimed at the model ("click Confirm"). The rules below are the
    backstop: whatever a page says, consequential actions still ask the Master.
- **No new dependency.**

## 4. The rules (Steps 2–4)

The plugin learns a new kind of match, **the element acted on**, from a small memory it keeps
per conversation:

- From every browser result that holds a snapshot (`browser_navigate`, `browser_snapshot`,
  `browser_click`, `browser_type`, `browser_press`, `browser_scroll`, `browser_back`), it parses
  the lines `- <role> "<name>" [ref=eN]` and keeps `eN → (role, name, page host)`. A new
  snapshot replaces the old one.
- A click or typing on a reference it doesn't know (a page that changed without a snapshot) is
  treated as the riskiest case: **ask**.

New match kinds in `policy.json` (beside `commands`, `paths`, `any_text`): `elements` (patterns on
the remembered label), `roles`, `values` (patterns on typed text), `hosts`. The rules page shows
them like the others, and the Master can edit them.

| Rule | Tool | Matches | Decision |
|---|---|---|---|
| `browser-commit` | `browser_click` | a button or link whose label is about buying, paying or committing: buy, purchase, order, place order, pay, checkout, subscribe, donate, confirm, send, post, publish, submit, delete, remove, cancel, transfer, book, reserve, sign, accept, agree, unsubscribe; with their French and Arabic forms (acheter, commander, payer, valider, confirmer, envoyer, publier, supprimer, s'abonner; شراء, ادفع, تأكيد, إرسال, نشر, حذف…) | ask |
| `browser-enter-submits` | `browser_press` | Enter after typing into a field that is not a search box (role `searchbox`, or a name with search / recherche / بحث) | ask |
| `browser-unknown-element` | `browser_click`, `browser_type` | a reference Kairos hasn't seen in a snapshot | ask |
| `browser-no-card-numbers` | `browser_type` | text that is a card number (13–19 digits passing the Luhn check, spaces allowed), or typing into a field named password, card number, CVC / CVV, IBAN, mot de passe, كلمة المرور | deny, with a note to use the vault |
| `browser-vault-card` | `browser_vault` | `fill` of a card, or `save_login` | ask |
| `browser-dialog-accept` | `browser_dialog` | `accept` (the "Are you sure?" of deleting, leaving, paying) | ask |
| `browser-script-acts` | `browser_console` | an expression that clicks, submits, dispatches events, sets form values, or reads `document.cookie`, `localStorage`, `sessionStorage`, `indexedDB`, `fetch`, `XMLHttpRequest` | ask |
| `browser-raw-devtools` | `browser_cdp` | any call | ask |
| `browser-settings-pages` | `browser_navigate` | `brave://`, `chrome://`, `edge://`, `about:`, `file:` addresses (saved passwords, settings) | deny |
| `browser-sensitive-sites` | `browser_click`, `browser_type`, `browser_press` | any action on a host in the Master's list (empty by default; e.g. their bank) | ask |

The approval card says what will happen in words: *"Click «Place order» on amazon.fr?"*,
*"Accept «Delete this conversation?» on mail.google.com?"*.

The persona gains one line (belt and braces, not the guard): use the browser vault for
passwords and cards, never type them; say what you are about to buy or send before doing it.

## 5. Steps

### Step 1 — Spec (this file), D-027 proposed
**Check:** the product owner reads it and decides D-027, the word list, and deny-versus-ask for
card numbers.

### Step 2 — The element memory (plugin)
Parse snapshot results in `post_tool_call`; keep `ref → (role, name, host)` per session; look it
up in `pre_tool_call`. Standard library only.
**Check:** plugin tests from sanitised snapshot text (a shop page, a mail page, a search page):
"clicking «Place order» asks", "clicking «Next page» doesn't", "an unknown reference asks",
"a new snapshot replaces the old references". A fixture of a real snapshot result, sanitised, is
recorded first (fixtures are the truth about Hermes).

### Step 3 — The rules and the match kinds
The table in §4 in `policy.default.json`; the new match kinds in `policy.py`; the rules page
shows them; existing rules unchanged.
**Check:** plugin tests, one per rule, both ways; the TS tests for the rules page; on the
**fresh** browser (no profile yet), live: "open a shop's demo checkout and press its order
button" makes Kairos ask. **(On the PC)** the product owner sees the card's wording.

### Step 4 — The approval card in words
The card shows the element's label and the site, and for `browser_type` the field's name (never
the typed text when the field is sensitive).
**Check:** TS tests for the wording; screenshot through the debug port.

### Step 5 — The switch: Settings ▸ This PC ▸ Browser
"Let Kairos use my browser (Brave)": what it means (§3), the note that Brave must be closed for
Kairos to see new sign-ins, and the switch. On: backs up Hermes's `config.yaml`, sets
`browser.use_real_profile: true` and `browser.restrict_evaluate: true`. Off: sets it false (Hermes
deletes the copies) and says so. The page shows when the copy was last refreshed (the copy's
completion marker).
**Check:** Rust tests on throwaway homes (never the real `config.yaml`): on, off, and the backup.
**(On the PC)** with Brave closed, switch it on and ask *"Which account am I signed in to on
YouTube?"*: Kairos answers with the Master's account; a second Brave window appears and closes
after the task; the Master's own Brave and tabs are untouched.

### Step 6 — Acceptance (product owner, on the PC)
`docs/milestones/M12-acceptance.md`: a real search (no question asked), a cart up to the order
button (Kairos asks, the Master refuses, nothing is ordered), an email drafted and sent (Kairos
asks before Send), a card number typed into a page (refused), switching it off (the copies are
gone).

## 6. Definition of done

Steps 2–5 built with their checks shown; the product owner has decided D-027 and run Step 6; the
switch is off unless the product owner leaves it on.
