## 1. Goal and scope

Kairos reaches the product owner's accounts the way D-010 says: each through its official
sign-in, never with a password given to Kairos, read-only by default, every write asking, each one
disconnectable from Settings.

**Kairos builds no sign-in of its own.** Hermes 0.22.5 already ships what is needed [source:
`skills/productivity/google-workspace/`]:

| Account | Sign-in | Where the secret lives | Used by the model through |
|---|---|---|---|
| **Google** (Gmail, Calendar) | Hermes's bundled `google-workspace` skill: Google's OAuth 2.0 with PKCE, using **the product owner's own Google Cloud OAuth client** (a "Desktop app" client created once in Google Cloud Console) | Hermes: `%HERMES_HOME%\google_token.json`, refreshed by Hermes | `python …/google-workspace/scripts/google_api.py gmail …`, `calendar …` in the terminal |
| **GitHub** | GitHub's own CLI login: `gh auth login --web` (a browser sign-in) | `gh`'s store (Windows Credential Manager) | `gh …` in the terminal |
| **Outlook** | — | — | **Not in M6.** Hermes 0.22.5 has no Microsoft sign-in skill; its IMAP route (`himalaya`) needs an app password, which D-010 rules out. Recorded as a gap |

**In scope:** Settings ▸ Accounts (status, connect, disconnect), the account rules, and the
briefing's AI summary using connected accounts.

**Out of scope:** Outlook (above), other accounts "on request" (each needs its own sign-in route),
Kairos-side OAuth.

## 2. Rules (D-010: writes always ask)

Three starter rules, offered to existing files by the Rules page:

| id | Tools | Matches | Action |
|---|---|---|---|
| `no-account-tokens` | file tools, terminal, `execute_code` | `**/hermes/google_token.json`, `**/hermes/google_oauth_pending.json`, `**/hermes/google_client_secret*.json`, `**/gh/hosts.yml` | deny |
| `account-writes` | terminal, `execute_code`, `browser_exec` | Gmail `send`, `reply`, `modify` (labels, read state, trash); Calendar `create`, `update`, `delete`; Drive `upload`, `share`, `delete`, `create-folder`; Sheets `update`, `append`, `create`; Docs `create`, `append` — whether called through `google_api.py`, `$GAPI` or `gws`; `himalaya` send, reply, forward, delete, move | ask |
| `account-disconnect` | terminal, `execute_code` | `setup.py --revoke` (the Google skill's disconnect), `gh auth logout`, `gh auth refresh` | ask |

Reading (`gmail search`, `gmail get`, `calendar list`, `gh pr list`) inherits: allowed, recorded.
`git-publish` (M2) already makes GitHub posts ask; `no-credential-store` already denies
`gh auth token`.

"Reply to X" therefore drafts, and the approval card shows the full command, recipient and body
included, before anything is sent.

## 3. Settings ▸ Accounts

| | Status | Connect | Disconnect |
|---|---|---|---|
| Google | Connected when `%HERMES_HOME%\google_token.json` exists (only its existence is checked; Kairos never opens it) | Starts a Kairos conversation asking Hermes to set up Google Workspace for **Gmail and Calendar**; the skill walks through the Google Cloud client and the browser sign-in | Runs the skill's own `setup.py --revoke` with Hermes's bundled Python (revokes at Google and deletes the token), after the page asks |
| GitHub | `gh auth status --hostname github.com` exit code (its output is never shown or logged: it can carry a masked token) | Opens a terminal window running `gh auth login --hostname github.com --web` | `gh auth logout --hostname github.com`, after the page asks |

Disconnecting is done by Kairos directly, not by the model, so it works even when the model
misbehaves. When `gh` or the Google skill isn't installed, the row says so.

## 4. Briefing

The M5 AI summary request gains, per connected account: Google — today's calendar events and the
number of unread emails (read-only commands); GitHub — open pull requests waiting for the user's
review (read-only). The instant facts stay native and offline: Kairos doesn't read account data
itself (D-010: tokens stay with Hermes and `gh`).
